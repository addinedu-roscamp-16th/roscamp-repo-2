# 실물 양팔 픽앤플레이스 개선 계획

범위는 실물 JetCobot 양팔의 계획, 실행, 정지·복구다. 물체 검출과 주문 UI는 이번 범위에서 제외한다. 현재는 매칭된 ROI ID를 주문 품목으로 지정하고 핑키 도착 시 작업자가 `E`로 첫 동작을 시작한다.

## 현재 구현

- 팔별 상태와 상품 구역·바구니 구역의 소유권을 관리한다. 담은 팔이 `see_center`로 복귀한 뒤 바구니를 해제한다.
- 첫 접근 계획이 끝나면 수동 실행을 기다리는 동안 두 번째 접근을 준비한다. 캐시를 쓸 수 없으면 복귀 경로의 예정 끝 자세를 기준으로 선행 계획한다. 저장 경로를 실행할 때는 실측 시작 자세 기본 3° 허용오차와 기존 실행 게이트 검사를 적용한다.
- 저장 경로 인계는 새 양팔 관절 피드백의 안정성을 확인한다. 8초 안에 안정되지 않으면 일시정지한다.
- `P`·`S`로 스케줄러를 일시정지하고 활성 동작에 취소를 요청한다. 실행 목표를 이미 보낸 경우 수락 응답을 회수한 뒤 취소하고, 종료를 확인하지 못하면 로그에 남긴다. 동작 실패 시 팔을 `paused`로 두거나 서비스 `error`로 전환하는 경로도 있다. 실패 이후 물체와 주문 상태를 대조하고 안전한 단계에서 이어가는 절차는 개발이 필요하다.
- 현재는 실행 게이트가 한 번에 한 목표를 처리한다. 기존 양팔 묶음 경로에서는 한 팔의 운반을 위해 상대 팔이 비켜줄 수 있다.

## 기존 시간 로그

| 기록 | 측정 범위 |
| --- | --- |
| `TIMING …`, `timing_log.csv` | 일반 worker의 단계·팔·시작 기준 경과 시간·소요 시간·종료 코드 |
| `STATE NEXT PLAN exit=… in … s` | 선행 접근 계획 worker 소요 시간과 종료 코드 |
| `TIME …` | 담기 worker의 계획, 실행, 복귀 등 단계별 및 누적 시간 |
| `TIME place release`, `TIME place lift` | 그리퍼 놓기와 놓은 후 들어 올리기 |

기존 로그로 가장 긴 단계부터 찾는다. 계획 worker가 오래 걸려도 팔이 동시에 움직였다면 그 전부가 작업 지연은 아니다. 비교할 때는 **양팔이 멈춘 상태에서 계획만 기다린 시간**, **앞 팔 복귀 완료부터 다음 팔 움직임까지 걸린 시간**, **동일 주문의 전체 완료 시간**을 본다. 로그만으로 구분이 어려운 지점에는 작업 ID와 함께 전환 시각을 기록한다. 우선 필요한 전환은 복귀 완료, 선행 계획 채택 또는 폐기, 게이트 목표 수락, 실제 움직임 시작이다.

## 우선순위

### 1. 실패 감지와 안전한 복구

- 정지 요청, 목표 취소 확인, 로봇 실제 정지를 각각 확인한다. 목표 수락이나 취소를 확인하지 못했으면 작업을 보류하고 확인이 필요한 상태를 남긴다.
- 접근 계획 실패, 접근·리프트 실행 실패, 집기 실패, 담기 중 실패를 구분한다. 각 경우에 상품 ID, 마지막으로 성공한 단계, 팔의 물체 보유 여부, 구역 소유권을 기록한다. 물체 보유나 바구니 투입 결과를 확인할 수 없으면 미확인으로 남긴다.
- 물체를 놓은 뒤 복귀에 실패했을 때 같은 주문을 다시 집는 일을 막는다. 구역은 실제로 비었음을 확인한 뒤 해제한다. 처음에는 작업자 확인을 거쳐 재시작할 단계만 선택할 수 있으면 된다.
- 실물 테스트에서는 첫 접근, 그리퍼 닫기, 운반, 놓기, 복귀에서 각각 중단하고 다음 동작이 자동으로 시작되지 않는지 확인한다. 통신 단절과 오래된 실측 피드백도 확인한다.

### 2. 작업 큐와 선행 계획 분리

- 지금은 선행 계획을 시작하면 상품을 큐에서 꺼내고 실패하거나 취소하면 다시 넣는다. 상품은 스케줄러가 작업을 확정할 때만 큐에서 꺼내고, 후보 계획은 주문·상품·팔에 연결해 보관한다.
- 복귀 worker의 사람이 읽는 로그를 다음 계획의 시작 신호로 사용한다. 복귀 경로가 실행 직전에 다시 계획될 수 있으므로, 확정된 경로의 끝 자세와 계획 시작 상태를 구조화된 데이터로 전달한다.
- 원래 상품 관측 시각과 최신 관절 확인 시각을 구분한다. 최신 관절값을 읽거나 경로를 다시 계산해도 최초 상품 좌표의 관측 시각은 유지한다. 상품이 이동했을 가능성이 있거나 허용 시간이 지났으면 해당 목표만 다시 확인한다.
- 선행 계획의 실패·만료·시작점 불일치를 같은 인계 단계에서 처리한다. 11월 20일에 발생했던 MoveIt 충돌 검사 요청 경합을 재현할 수 있도록 타임아웃 구간을 기록한다. 실행 검사와 계획의 경합이 반복되는 경우 계획 전용 인스턴스를 검토한다.

### 3. 실제 양팔 협동 구간 한 개 검증

- 상품 두 개로 시작한다. 첫 팔이 바구니로 운반할 때 상대 팔의 비켜주기 목표 대신, 다음 주문 상품의 접근 자세를 양팔 묶음 경로의 후보로 사용한다.
- 상품 구역 해제와 바구니 구역 소유권을 지킨다. 물체를 든 팔의 부착 모델과 양팔 동시 움직임을 포함해 경로를 검사한다. 조건을 충족할 수 없으면 현재 순차 경로를 사용한다.
- 상대 팔이 먼저 접근을 끝낸 경우, 이후 단계는 실제 관절 피드백과 해당 단계의 자원 조건을 확인한 뒤 진행한다. 정지·실패가 나면 두 팔의 진행 상태를 함께 보존한다.
- 동일한 상품 배치에서 순차 실행과 묶음 경로의 전체 완료 시간과 양팔 동시 움직임 시간을 비교한다.

### 4. 팔 배정과 계획 대기 최적화

- 현재는 좌우 교대 순서를 유지하고 상대 팔과의 거리 차이로 각 팔의 상품을 고른다. 선택한 팔이 해당 상품에 접근할 수 없으면 다른 상품이 가능해도 진행이 끊길 수 있다.
- 각 팔 차례에 가까운 후보 몇 개부터 도달 가능성을 확인한다. 가능한 후보가 여럿이면 반대 팔의 작업과 겹칠 수 있는 시간, 예상 실행 시간, 추가 양보 동작을 기준으로 선택한다. 비교는 핑키 이동 시간이나 앞 작업 중 계획 여유에 수행한다.
- 기준 도킹 자세와 `see_center`를 활용해 접근 외에 담기·복귀 구간의 재사용 가능성을 확인한다. 실제 도킹 위치나 집기 후 자세가 달라졌으면 영향을 받는 구간만 다시 계산한다.
- 현재 `HOLD_RETURN`을 가정하는 일부 테스트는 직접 담기 흐름과 맞지 않는다. 현재 흐름의 상태 전이, 취소 후 추가 명령 방지, 캐시 인계·폐기 조건으로 갱신한다.

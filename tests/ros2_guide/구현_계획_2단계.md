# ROS 2 통신 안내 시험 2단계 (L-01-W, L-02, L-04, G-11) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 저녁에 PC와 라즈베리파이 1대로 L-01-W, L-02, L-04, G-11을 명령 하나(`run_stage2.sh`)로 실행하고, 끊기면 남은 조합만 이어서 실행하며, 항목마다 판정이 담긴 JSON을 남기는 시험 도구를 만듭니다.

**Architecture:** 1단계의 구조(순수 Python 판정 모듈 `r2g/` + 얇은 노드 `nodes/` + 지휘 스크립트 `run_*.py`)를 그대로 따릅니다. 새로 `r2g/remote.py`의 실행기(Launcher)가 "라즈베리파이 쪽" 노드를 SSH로 띄웁니다. `PI_HOST=local`이면 같은 노드를 PC에서 띄우므로, 낮에 PC만으로 전체 흐름을 미리 돌려 볼 수 있습니다. 라즈베리파이 쪽 노드는 결과를 표준 출력의 마지막 JSON 줄로만 돌려주고, 두 장비의 시계는 비교하지 않습니다.

**Tech Stack:** Python 3.12, ROS 2 Jazzy rclpy, `std_msgs/msg/String`, PyYAML, OpenSSH(`BatchMode`), rsync, GStreamer(`gst-launch-1.0`, `x264enc`: 라즈베리파이에 있음을 확인함), pytest

**Spec:** [ROS2_통신_안내_시험_계획서.md](../ROS2_통신_안내_시험_계획서.md) 3.1절(L-01-W, L-02, L-04), 3.3절(G-11)과 8장 G-11 검토 의견, 5장 2단계, 6장

## Global Constraints

- **1단계 공식 실행이 끝날 때까지 ROS 실행 확인과 커밋을 하지 않습니다.** 1단계 결과의 `tool_commit`이 실행 중에 HEAD를 읽고, ROS 실행 확인은 같은 PC의 CPU와 도메인을 씁니다. 그동안에는 파일 작성과 단위 시험(`pytest`)까지만 합니다.
- 위치: 팀 저장소 `tests/ros2_guide/`. 1단계 파일의 동작을 바꾸지 않습니다. 1단계 단위 시험 84개가 계속 통과해야 합니다.
- 팀 `ruff.toml`: line-length 100, py312, 규칙 E, F, I, B.
- `std_msgs`만 사용합니다(라즈베리파이에서 인터페이스 빌드 없음). QoS는 `contract.yaml`의 `STATE`, `LATCHED`, `EVENT`를 `r2g/qos.py`로 읽습니다.
- 라즈베리파이 연결: `PI_HOST`(기본 `local`), SSH 옵션 `-o BatchMode=yes -o ConnectTimeout=5`. 원격 폴더는 `~/r2g/`이고, 그 아래에 저장소와 같은 상대 경로로 `tests/ros2_guide/`와 `interfaces/fleet_interfaces/contract.yaml`을 복사합니다(`qos.py`가 `parents[3]`로 찾기 때문).
- 통신 범위: 장비 2대이면 PC와 라즈베리파이 모두 `ROS_AUTOMATIC_DISCOVERY_RANGE=SUBNET`(G-11의 격리 조건만 예외), `PI_HOST=local`이면 모두 `LOCALHOST`. `ROS_DOMAIN_ID`는 양쪽 같은 값(없으면 87).
- 결과 값은 `통과`, `실패`, `미실행`, `판정 불가`, `측정`. 항목마다 JSON 1개(`results.write_result`). 결과 폴더는 커밋하지 않습니다.
- 공식 크기: L-01-W 변형마다 50회, L-02 조합마다 30초·3회, L-04 조합마다 120초, G-11 방향마다 관찰 10초. 이 크기가 아니면 규칙 판정(L-01-W B, C, E-TL, S와 G-11)은 `판정 불가`이고 모든 결과에 "개발 실행(…): 공식 판정 아님" 메모를 붙입니다(1단계 `judge.size_gate`와 같음).
- `PI_HOST=local`이면 규칙 판정은 `판정 불가`이고 모든 결과에 "장비 1대(PI_HOST=local): 공식 판정 아님" 메모를 붙입니다.
- 두 장비의 시계를 서로 빼지 않습니다. 끊김·간격은 한 장비 안의 단조 시계(`time.monotonic_ns()`)로만 잽니다.
- 커밋 메시지는 Conventional Commits(영어 제목), 끝에 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. `tests/.gitignore`와 `tests/참조/`는 커밋하지 않고, 파일을 하나씩 지정해 `git add` 합니다.

## Review Focus

- 저녁 실행 중 SSH가 끊기거나 시간 초과가 나서 라즈베리파이에 노드가 남음: 다음 조합에 섞이면 안 됨 → Task 1 `RemoteLauncher`가 시간 초과 때 원격 PID를 kill하는 명령을 만드는 시험, Task 6 시작·종료 때 `cleanup()` 호출.
- 실행이 중간에 끊김: 다시 실행하면 끝난 조합은 건너뛰고 남은 조합만 돌아야 하며, `--resume` 없이 같은 실행 ID를 쓰면 거부해야 함 → Task 1 `parts` 시험, Task 6 `--resume` 시험.
- PC 방화벽이나 공유기 설정 때문에 두 장비가 서로 통신하지 못함: 1시간 45분을 돌린 뒤가 아니라 시작 직후 멈춰야 함 → Task 6 사전 점검 `preflight_verdict` 시험.
- 두 장비의 시계가 다름: 장비 간 시각 차이를 계산에 쓰면 손실·끊김 값이 틀어짐 → Task 3 `max_interval_ms`, Task 4 `heartbeat_gaps`가 한 장비의 시각만 받는 시험.
- 500 KB × 50 Hz처럼 Wi-Fi가 감당하지 못하는 조합: 발행 노드가 늦게 끝나도 전체 실행이 멈추지 않고 그 조합에 사유를 남긴 뒤 다음 조합으로 넘어가야 함 → Task 3 `l02_problem` 시험(발행 노드 시간 초과, 발행 수 미달).

    - `start(script: str, args: list[str], env_over: dict[str, str]) -> subprocess.Popen`: `nodes/<script>`를 띄움
    - `start_command(command: str, env_over: dict[str, str]) -> subprocess.Popen`: 노드가 아닌 명령(L-04의 GStreamer 송신)을 같은 방식(원격은 `pi_exec.sh` 경유, `PID` 줄)으로 띄움

    - `stop(p: subprocess.Popen) -> None`
    - `shell(command: str, timeout: float) -> proc.ChildResult`: 그 장비에서 셸 명령(ROS 환경 없이)
    - `cleanup() -> None`: 그 장비에 남은 `ros2_guide/nodes/` 프로세스와 `gst-launch-1.0`을 모두 종료
  - `remote.LocalLauncher(env: dict[str, str])`: `proc.*`를 그대로 씀. `env_over`는 `env`에 덮어씀. `host = "local"`.
  - `remote.RemoteLauncher(host: str, domain_id: str)`: `ssh SSH_OPTS host bash r2g/tests/ros2_guide/nodes/pi_exec.sh KEY=VAL ... -- python3 -u r2g/tests/ros2_guide/nodes/<script> <args>` 형식(인자는 `shlex.quote`).
  - `remote.remote_cmd(host: str, script: str, args: list[str], env_over: dict[str, str]) -> list[str]`: 위 명령 목록(시험 대상)
  - `remote.parse_pid(stdout: str) -> int | None`: 첫 `PID <n>` 줄
  - `remote.kill_cmd(host: str, pid: int, signal: str) -> list[str]`: `ssh SSH_OPTS host kill -<signal> <pid>`
  - `remote.make_launcher(pi_host: str, env: dict[str, str]) -> Launcher`: `"local"`이면 `LocalLauncher`
  - `remote.sync(host: str, repo_root: Path) -> proc.ChildResult`: rsync `-az --delete`, 제외 `results/`, `__pycache__/`, `unit/`, `.pytest_cache/`
  - `remote.wifi_info(launcher: Launcher) -> dict`: `{"signal_dbm": int | None, "link_quality": str | None, "raw": str}`. 원격에서 `iwconfig wlan0`, local이면 `raw = "PI_HOST=local"`
  - `remote.parse_iwconfig(text: str) -> dict`: 위 dict
  - `remote.pc_address_seen_by(host: str) -> str | None`: `ssh host 'echo $SSH_CLIENT'`의 첫 칸(L-04 영상 수신 주소)
  - `remote.pi_env(launcher: Launcher) -> dict`: 그 장비의 `ROS_DISTRO`, `RMW_IMPLEMENTATION`(없으면 `"기본"`), `host`, `arch`. 2단계 결과의 `conditions.pi_env`와 사전 점검에 기록
  - `parts.part_path(run_dir: Path, test_id: str, key: str) -> Path`: `<run_dir>/parts/<test_id>/<key>.json`
  - `parts.save_part(run_dir: Path, test_id: str, key: str, data: dict) -> Path`: 있으면 `FileExistsError`
  - `parts.load_part(run_dir: Path, test_id: str, key: str) -> dict | None`
  - `parts.done_keys(run_dir: Path, test_id: str) -> set[str]`
  - `config.CONFIG = HERE / "stage2.yaml"`, `config.load(path: Path = CONFIG) -> dict`

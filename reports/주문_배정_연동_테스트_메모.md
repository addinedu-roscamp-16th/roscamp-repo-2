# 주문 → Pode 배정 연동 테스트 보고서 메모

보고서(`Integration Test Report Example.pdf` 틀)를 쓰기 전에 모아 둘 것만 적습니다. 내용 · 형식은 fleet 주문 코어 개발을 마친 뒤 정합니다.

## 목적

주문을 받아 Pode 배정까지의 데이터 흐름을 확인합니다. 실 주행은 하지 않고, 연동되어 데이터가 전달되고 응답을 받는지가 목적입니다.

### 사유 · 단서

- T-01: 첫 `SubmitTrip` 호출은 응답 없음(1/5)이었고, 같은 운반 건 id로 다시 보낸 호출에서 `accepted=True`로 접수됐습니다. 중복 접수는 없습니다(SB-06).
- T-02: 이번 브랜치에서 다시 돌리지 않았고, 서비스 브리지 첫 조각(#14)의 시험이 근거입니다.
- T-04 · T-06: 작업대 호출과 도착 응답은 fleet 프로세스 안의 명령이라 ROS 토픽에 나오지 않습니다. 코어 통합 시험의 기록 줄로 확인했고, ROS 연동 실행에서는 그 결과(`ORDER_SENT`, `DOCKED`)로 확인했습니다.
- T-07: `ORDER_BOUND`는 `/central/events` 토픽으로 확인했습니다. 함께 내는 `ReportTripCmd(ASSIGNED)`는 코어 출력까지만 확인했습니다(T-10).
- T-09: ROS 연동 실행에서는 용량 초과 주문을 넣지 않았습니다.
- T-10 (보류): 주문 코어는 배정 보고(`ReportTripCmd(ASSIGNED)`)를 내지만, fleet 노드가 이를 브리지(`/bridge/report_trip`)로 보내는 코드가 아직 없습니다(TT-27). 지금 노드는 이 명령을 받아도 아무것도 하지 않아, DB의 운반 건은 처음 상태로 남습니다. 브리지의 수신과 DB 반영은 #14에서 시험했습니다.

### 관찰 사항 (실패 아님)

- 채우기(pseudocode 4장)가 아직 없어 한 번에 한 Pode만 배정됩니다. 두 번째 주문이 들어오면 다른 Pode는 작업대 대기열에서 기다립니다(`DOCK_QUEUED WORK is busy`).
- ROS 연동 실행에서 가짜 Pode의 위치 경고(`LOCALIZATION_SUSPECT`, 0.1초에 약 0.2 m)가 몇 번 나왔으나 흐름에는 영향이 없었습니다.

- 실행: `setup_db` → `central` → `pc.launch.py use_fake:=true fake_central:=false scenario:=real_two_orders robots:="pode1 pode2" fake_robots:="pode1 pode2"` → `ros2 bag record /central/orders /central/events /fleet/assignments` → `submit_trip --items A:1,C:1` 한 번
- 통신: 개인 도메인, `LOCALHOST`(디스커버리 서버 없음)
- 기록: `bags/order_assign_4` (mcap, 메시지 799개 — orders 781 · events 15 · assignments 3), 글로 뽑은 것 `bags/order_assign_4.txt`. `bags/`는 git에 넣지 않습니다.

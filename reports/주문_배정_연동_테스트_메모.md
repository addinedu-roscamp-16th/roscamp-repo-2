# 주문 → Pode 배정 연동 테스트 보고서 메모

보고서(`Integration Test Report Example.pdf` 틀)를 쓰기 전에 모아 둘 것만 적습니다. 내용 · 형식은 fleet 주문 코어 개발을 마친 뒤 정합니다.

## 목적

주문을 받아 Pode 배정까지의 데이터 흐름을 확인합니다. 실 주행은 하지 않고, 연동되어 데이터가 전달되고 응답을 받는지가 목적입니다.

## 시험 항목 초안

| No | 구간 | 테스트 내용 | 기대 결과 |
|---|---|---|---|
| T-01 | 시험 도구 → DB · central | 운반 건 넣기와 접수(`SubmitTrip`) | 접수 응답을 받음 |
| T-02 | fleet → 브리지 → DB | `Hello` · `ReportTrip` 반영 | 상태가 DB에 반영됨 |
| T-03 | central → fleet | 주문판 전달 | fleet이 주문판을 받아 저장 |
| T-04 | 주문 코어 → 교통 층 | 작업대 호출 | 대기 주문 수만큼 호출이 열림 |
| T-05 | 교통 층 → Pode | Pode 선택 · 이동 명령 | 가능한 Pode에 이동 명령이 나감 |
| T-06 | 교통 층 → 주문 코어 | 도착 응답 | 성공 응답과 Pode 이름이 옴 |
| T-07 | 주문 코어 → central | 배정 알림(`ORDER_BOUND`, `ReportTripCmd(ASSIGNED)`) | 주문과 Pode가 실림 |
| T-08 | fleet → 화면 | 배정 조회(`/fleet/assignments`) | Pode · 주문 · WORK · FILL |
| T-09 | 예외 | 바구니 용량 초과 주문 | 경고 1회, 다른 주문은 배정됨 |
| T-10 | fleet → 브리지 | `ReportTrip(ASSIGNED)` 전송 | DB가 배정됨으로 바뀜 |

- T-01 · T-02는 서비스 브리지 첫 조각(#14) 시험이 근거입니다.
- T-03 ~ T-09는 코어 통합 시험(ROS 없음, 실 주행 없음)으로 확인합니다. T-03의 ROS 토픽 수신은 확인 범위 밖입니다.
- T-10은 보류입니다(노드의 ReportTrip 전송, TT-27).

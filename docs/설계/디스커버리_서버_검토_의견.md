# 디스커버리 서버 검토 의견

- 검토일 2026-11-24 · 대상 브랜치 `docs/discovery-server` (`da5feb6`)
- 검토 문서 [디스커버리 서버 안내](디스커버리_서버_안내.md) · [ROS 2 QoS 호환과 통신 안내](ROS2_QoS_통신_안내.md) · [통신 규칙](통신_규칙.md)

배포 전에 개인 시험과 통합 시험의 환경 설정을 고치고, 기존 실물 Pode 실행 경로를 새 설정과 맞출 것을 제안합니다. 같은 Discovery Server에 연결된 노드를 `ROS_DOMAIN_ID`만으로 분리할 수 없다는 IR-82의 설명은 Fast DDS 2.14 공식 문서와 일치합니다. [Fast DDS 2.14 Discovery Server 설정](https://fast-dds.docs.eprosima.com/en/2.14.x/fastdds/discovery/discovery_server.html)

## 1. 높음 — 개인 시험 예제에 운영 서버 주소가 남음

QoS 안내 항목 10에서 운영 설정과 개인 시험 설정을 같은 셸에서 차례로 적용하면 `ROS_DOMAIN_ID=43`, `ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST`로 바뀌어도 `ROS_DISCOVERY_SERVER=192.168.0.252:11811`이 남습니다. IR-81이 요구하는 개인 시험 환경은 서버 설정이 비어 있어야 합니다. [QoS 안내 항목 10](ROS2_QoS_통신_안내.md) · [통신 규칙 IR-81](통신_규칙.md)

**제안** — 운영·개인 시험 예제를 모두 `net_ds.sh` 호출로 바꿉니다. 아래 개인 시험 명령은 이전 서버 설정을 지웁니다. 운영 설정을 적용한 셸에서 이 명령을 실행한 뒤 서버 환경 변수가 해제되는 것을 확인했습니다. [설정 스크립트](../../tools/net/net_ds.sh)

```bash
FLEET_DOMAIN_ID=43 FLEET_LOCAL=1 source "$IPONIC_REPO/tools/net/net_ds.sh"
```

## 2. 높음 — 통합 시험 주소가 비어 있으면 운영 서버가 선택됨

`FLEET_DOMAIN_ID=43 FLEET_DS= source tools/net/net_ds.sh`를 실행하면 `FLEET_DS`가 비어 있어도 스크립트가 성공하고 `ROS_DISCOVERY_SERVER=192.168.0.252:11811`을 설정합니다. 시험 도메인으로 설정해도 운영 서버에 연결될 수 있습니다. [디스커버리 서버 안내 5절](디스커버리_서버_안내.md) · [설정 스크립트](../../tools/net/net_ds.sh)

**제안** — 여러 PC에서 시험할 때는 시험용 서버 목록을 필수로 받습니다. 누락하거나 빈 값을 넘긴 경우 운영 주소로 진행하지 않도록 설정을 실패 처리하고 노드 시작을 중단합니다. 문서 예제에서는 세미콜론이 들어갈 수 있는 서버 목록 전체를 `FLEET_DS="$TEST_DISCOVERY_SERVERS"`처럼 따옴표로 감쌉니다. 시험 서버의 실제 주소·포트는 Q-18에서 결정합니다. [설계 검토 사항 Q-18](설계_검토_사항.md)

## 3. 높음 — 기존 Pode·RViz 실행 경로가 도메인 12를 설정함

실물 Pode의 `start.sh`는 자체 `env.sh`를 읽습니다. `env.sh`와 `rviz_pc.sh` 모두 도메인 `12`를 직접 설정하고 Discovery Server 주소를 설정하지 않습니다. 이전 설정이 없는 셸에서는 Discovery Server 주소 없이 실행되며, `net_ds.sh`를 먼저 읽어도 실행 과정에서 도메인이 다시 `12`로 바뀝니다. [Pode 시작 스크립트](../../tools/real_pode/start.sh) · [Pode 환경 설정](../../tools/real_pode/env.sh) · [RViz 실행 스크립트](../../tools/real_pode/rviz_pc.sh)

**제안** — 현재 배포에 사용하는 실행 경로를 확인한 뒤 `net_ds.sh`로 통합하거나, 새 실행 절차와 기존 스크립트의 적용 범위를 안내서에 명시합니다. 배포 확인 시 실제로 구동한 노드가 도메인 `6`, `rmw_fastrtps_cpp`, 의도한 서버 목록을 물려받았는지 확인합니다. [디스커버리 서버 안내 5·7절](디스커버리_서버_안내.md)

## 4. 중간 — 서버 장애 전환 설명과 시험 조건을 맞춰야 함

| 항목 | 현재 시험 또는 문구 | 보완 제안 |
|---|---|---|
| C5 · IR-83 | 기존 노드가 통신 중일 때 서버 0만 끄고 서버 1은 유지합니다. | 두 서버가 모두 중단된 경우의 근거로 C5를 쓰려면, 기존 통신을 시작한 뒤 두 서버를 끄는 시험을 별도로 추가합니다. |
| C6 | talker가 서버 1만, listener가 서버 0만 아는 구성에서 서버 1을 끈 상태로 실행합니다. | 두 서버를 모두 켜고 각 노드가 서로 다른 서버 하나에 연결된 조건에서 수신 여부를 확인합니다. |
| C8·C9 | 서버 0만 아는 기존 장치와 두 서버를 아는 장치가 서버 0이 살아 있는 동안 함께 동작합니다. | 서버 0만 아는 장치는 서버 0 중단 후 새 연결을 서버 1로 전환할 수 없다고 안내합니다. 이중화를 적용하려는 장치에는 두 주소를 배포합니다. |
| 8절 실물 시험 계획 | central 서버를 끄는 절차를 C2로 표기합니다. | fleet 서버 0을 끄고 새 노드를 띄우는 C2와 central 서버 1을 끄고 새 노드를 띄우는 C3를 각각 시험합니다. |

## 확인 범위

셸 구문 검사와 환경 변수 전환은 로컬에서 확인했습니다. C2~C9는 저장소의 시험 스크립트와 문서에 기록된 결과를 대조했습니다. 검토 환경에서 UDP 소켓 생성이 제한되어 ROS 통신 시험은 재실행하지 못했습니다. Confluence 원시험 자료에도 접근하지 못했습니다.

## 응답 (2026-11-24)

4건 모두 원문과 대조해 맞다고 확인하고 같은 브랜치에 반영했습니다. 4번은 새 조건으로 다시 시험했습니다(`tools/net/test_two_servers.sh`, C1 ~ C11).

| 1. 개인 시험 예제에 운영 서버 주소가 남음 | 수용 (재현함) | QoS 안내 항목 10 예제를 `net_ds.sh` 호출로 바꿈. 직접 설정할 때는 `unset ROS_DISCOVERY_SERVER ROS_SUPER_CLIENT`를 먼저 하라고 적음 |
| 2. 통합 시험 주소가 비어 있으면 운영 서버가 선택됨 | 수용, 범위를 넓힘 | `FLEET_DS`를 빈 값으로 넘긴 경우뿐 아니라 **도메인이 6이 아닌데 `FLEET_LOCAL=1`도 `FLEET_DS`도 없는 경우**(같은 결과)도 `net_ds.sh`가 아무 값도 바꾸지 않고 실패(`return 1`). 개인 작업에 도메인 6을 준 경우도 경고에서 실패로. 예제는 `source … && ros2 launch …`, 서버 목록은 따옴표로. 8가지 조합으로 확인 |
| 3. 기존 Pode · RViz 실행 경로가 도메인 12 | 수용 | 관제 담당 스크립트라 이번에는 고치지 않음. 안내 5절에 적용 범위(전환 전에는 섞어 시험하지 않음, 전환 뒤 실제 노드 값 확인)를 적고, 설계 검토 사항 3장 "관제 팀에 넘길 일"에 전환 작업을 올림 |

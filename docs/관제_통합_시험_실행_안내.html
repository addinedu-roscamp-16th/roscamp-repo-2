1. 조건

무엇이번 시험
Pode(핑키)2대(pode1 · pode2) 실제 주행
팔모두 실물 (Phody arm_left · arm_right, Phony arm_ship)

PC 명령은 각자 colcon 작업 공간 폴더(src/ 위 폴더)에서 칩니다. 이 안내의 명령은 저장소가 src/roscamp-repo-2에 있다고 봅니다. 다른 곳이면 경로를 자기 것으로 바꿉니다.

켜는 순서: 디스커버리 서버(3절) → 로봇(4절) → 관제(5절). 팔 · central · 브리지(6절)는 서버가 켜진 뒤 아무 때나 켜도 됩니다.

2. PC 빌드

최신 브랜치를 받은 뒤 작업 공간 폴더에서 빌드합니다.

source /opt/ros/jazzy/setup.bash && colcon build

3. 디스커버리 서버

원문의 "제 노트북"(관제 담당 노트북)에서 띄웁니다. 실물 망의 0번 서버 주소는 tools/net/net_ds.sh의 DS_FLEET=192.168.0.252:11811이므로, 이 노트북의 주소가 192.168.0.252여야 합니다. 다른 장치는 모두 이 주소로 서버를 찾습니다.

직접 칠 때는 터미널에서:

source /opt/ros/jazzy/setup.bash && unset ROS_DISCOVERY_SERVER ROS_SUPER_CLIENT && fastdds discovery -i 0 -p 11811

시험이 끝날 때까지 켜 둡니다. 끌 때는 Ctrl+C.

  • 켜져 있는지는 서버 PC에서 아래로 봅니다(한 줄이 나오면 켜져 있음). 이미 켜져 있으면(예: systemd iponic-discovery@0) 또 켜지 않습니다. 출처: 디스커버리 서버 안내 6절.
ss -uln | grep ':11811'
  • 같은 일을 하는 저장소 스크립트는 tools/net/discovery_server.sh 0입니다(포트가 쓰이고 있으면 켜지 않음). 위 명령과 둘 중 하나만 씁니다.
  • 서버는 도메인과 상관없이 하나로 띄웁니다. fastdds discovery에는 도메인 인자가 없고, 같은 서버에 붙은 노드는 도메인이 달라도 서로 섞입니다(디스커버리 서버 안내 8절, 2026-11-24 관제 담당 실측). 실물 망 도메인은 6입니다.
  • 1번 서버(central PC)는 주소가 아직 정해지지 않았습니다(Q-20). 이번 시험은 0번 서버 하나로 돕니다.

4. 로봇 실행 (pode1 · pode2)

로봇마다 새 터미널을 엽니다. 로봇은 주차 자리 P-1 · P-2에 +y 방향으로 놓습니다.

먼저 다른 비전 · 주행 스크립트가 돌고 있지 않은지 확인합니다. 아무것도 안 나와야 합니다.

ps aux | grep -E "yolo|sensor_fusion|aruco|lidar_filter" | grep -v grep
cd ~/nav2fleet_real

pode1

DOCK_STUB=1 PEER_ROBOTS=pode1,pode2 ./start.sh pode1 0.12 0.10 1.5708

pode2

DOCK_STUB=1 PEER_ROBOTS=pode1,pode2 ./start.sh pode2 0.38 0.10 1.5708

끄기

./stop.sh

명령 풀이

start.sh의 인자 순서는 start.sh 로봇이름 x y yaw [속도]입니다(속도를 안 주면 0.12 m/s). 출처: tools/real_pode/start.sh 머리 주석.

로봇자리x (m)y (m)yaw (rad)
pode1P-10.120.101.5708 (+y 방향)
pode2P-20.380.101.5708 (+y 방향)
앞에 붙인 값뜻 (start.sh 머리 주석)
DOCK_STUB=1로봇의 Dock 서버를 /<ns>/dock_fsm으로 비켜, 도킹을 PC 대역(5절 dock_wait_robots)이 받게 함
PEER_ROBOTS=pode1,pode2두 대 이상일 때 서로 피하는 peer 층을 켬 (안 주면 꺼짐)

~/nav2fleet_real은 로봇에 배포된 폴더입니다. 저장소 쪽 원본은 tools/real_pode/start.sh · stop.sh이고, PC에서 tools/real_pode/deploy.sh로 로봇에 복사합니다(커밋된 HEAD만 감). 배포는 관제 담당이 하므로 여기서는 참고로만 적습니다. start.sh는 뒤에서 띄우고 기록을 ~/nav2fleet_real/logs/launch_*.log에 남깁니다.

5. 관제 실행

관제 PC에서 새 터미널을 열고, colcon 작업 공간 폴더(src/ 위)에서 칩니다. 저장소가 src/roscamp-repo-2에 있다고 봅니다. net_ds.sh는 안에서 /opt/ros/jazzy/setup.bash를 source하므로 앞에 따로 넣지 않습니다(tools/net/net_ds.sh).

source src/roscamp-repo-2/tools/net/net_ds.sh && source install/setup.bash && ros2 launch iponic_bringup pc.launch.py use_fake:=true use_sim_clock:=false fake_robots:=none fake_arms:=none fake_central:=false monitor:=false robots:="pode1 pode2" map_file:=v7 scenario:=real_two_orders dock_wait_robots:="pode1 pode2"
use_fake:=true는 PC 도킹 대역을 띄우려고 둡니다. 가짜 로봇 · 팔 · central은 모두 꺼져 있습니다. scenario는 도킹 대역의 대기 시간만 정하고 주문을 넣지 않습니다. 주문은 central · 브리지 쪽에서 넣습니다.

인자 풀이

인자와 기본값은 bringup/iponic_bringup/launch/pc.launch.py에서 확인했습니다. 이 줄은 파일 머리 주석의 "실물 두 대 시험" 예에 fake_arms:=none · fake_central:=false를 더한 것입니다.

6. 팔 · central · 브리지 담당에게

평소처럼 iponic_real(또는 source net_ds.sh)을 한 뒤 노드를 띄우면 됩니다.

iponic_real

iponic_real은 개발 규칙의 ~/.bashrc 예에 있는 함수입니다(source "$IPONIC_REPO/tools/net/net_ds.sh"). 넣지 않았다면 작업 공간 폴더에서 아래처럼 합니다.

source src/roscamp-repo-2/tools/net/net_ds.sh
  • 브리지 · central 실행은 1차 연동 실행 안내 5절을 따르되, 통신 설정은 iponic_local 대신 iponic_real로 합니다. 그 안내 5절의 터미널 3(fake_fleet · pc.launch.py)은 띄우지 않습니다. fleet은 5절의 관제 실행이 띄웁니다.
  • 브리지는 mode:=NORMAL로 띄웁니다(TEST면 주문이 503 MAINTENANCE).
  • 켜는 순서는 상관없습니다. central은 브리지를 찾을 때까지 "연결 중"(CONNECTING)으로 기다리고, 브리지가 뜨면 저절로 "주문판 갱신 중" → "실행 중"으로 넘어갑니다.
  • 팔 담당은 각 팔 노드를 같은 실물 망 설정으로 띄웁니다(팔 노드 실행 명령은 각 담당의 안내를 따름).

7. 주의 사항

  • 팔이 모두 실물입니다(fake_arms:=none). 그런데 주문 흐름 1차 인터페이스의 "남은 것"(2026-11-28)에는 Phony /arm_ship/swap_basket 서버와 Phody set_pause가 아직 없다고 되어 있습니다. 시험 전에 출고(Phony) · 양팔(Phody) 담당에게 준비됐는지 확인합니다.
  • 주문은 브리지에서 넣습니다: 고객 화면(http://<관제 PC>:8000/customer/?account=<id>) 또는 python -m service_bridge.tools.order. 사용법은 1차 연동 실행 안내 6절. 시나리오(real_two_orders)는 주문을 넣지 않습니다.
  • fake_fleet이나 board_trips_stub은 같은 도메인(6)에서 띄우지 않습니다. fake_fleet은 진짜 fleet과 겹치고, board_trips_stub은 central을 빈 목록으로 실행 중으로 만들고 /system/mode를 TEST로 덮어씁니다.
  • 모든 터미널을 실물 망으로 맞춥니다. 노드를 띄우기 전에 echo $ROS_DOMAIN_ID $RMW_IMPLEMENTATION $ROS_DISCOVERY_SERVER가 6 rmw_fastrtps_cpp 192.168.0.252:11811로 시작하는지 봅니다(디스커버리 서버 안내 7절). 전체 그래프를 볼 터미널(ros2 · RViz)은 super client(iponic_super)로 합니다.
  • 로봇은 DOCK_STUB=1로 띄웁니다. 빠뜨리면 로봇의 Dock 서버와 PC 도킹 대역이 같은 이름으로 겹칩니다(도킹 대역이 같은 이름의 서버를 찾아 알림).
  • 디스커버리 서버는 시험이 끝날 때까지 끄지 않습니다.

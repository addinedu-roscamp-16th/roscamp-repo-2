## 규칙

- **번호는 바꾸지 않습니다.** 설계 문서 · 코드가 기능 번호를 참조하므로, 빼는 기능은 지우지 않고 구현 계획에 "폐기"로 표시합니다. 새 기능은 그 앞자리의 다음 번호를 씁니다.
- **버전 `vX.Y`**: 시트 변경을 모아 이 사본으로 내보낼 때마다 Y+1, 스프린트 범위 확정이나 대규모 재편 때 X+1.
- 시트 "변경 이력" 탭의 **버전(H열)** 은 내보낼 때 채웁니다. 빈 칸 = 아직 저장소에 들어오지 않은 변경입니다.

## 갱신 절차

1. 시트 "변경 이력"에서 버전 칸이 빈 행을 확인합니다 (이번에 들어갈 변경).
2. "기능 목록" 탭을 CSV로 내보내 `기능_목록.csv`를 바꿉니다 ("Jira 스프린트" 열 제외, UTF-8).
3. 시트 "변경 이력"의 빈 버전 칸을 새 버전으로 채웁니다.
4. 이 README 머리(버전 · 날짜 · 기능 수 · 이력 범위)와 아래 변경 이력을 고칩니다.
5. `dev`에서 만든 브랜치로 PR을 엽니다. 제목 예: `docs(기능): 기능 목록 v1.1 (이력 75 ~ 82번)`.

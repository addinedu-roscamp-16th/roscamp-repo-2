# 주문 관리 DB (ERD · DDL) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 주문 관리 DB를 DBML 원본 하나로 만들고, 거기서 PostgreSQL DDL과 ERD 그림을 뽑는다. DB에 거는 규칙(CHECK · 부분 UNIQUE · 원장 트리거 · 마감 검사 · 뷰 · NOTIFY)은 손으로 쓴 SQL로 더하고 시험으로 확인한다.

**Architecture:** `design/db/order_db.dbml` → (Docker의 `dbml2sql`) → `order_db.sql`(손대지 않음) → 그 위에 `order_db_extra.sql`(DBML로 못 쓰는 것). 시험은 Docker의 PostgreSQL 16에 두 파일을 차례로 적용한 틀 DB를 만들고, 시험마다 그 틀에서 새 DB를 복사해 pytest + psycopg로 확인한다.

**Tech Stack:** PostgreSQL 16 (`postgres:16` 이미지), `@dbml/cli`의 `dbml2sql` (`node:20-alpine` 이미지에서 npx), Python 3.12 + pytest + psycopg 3 (`uv run --with`), dbdiagram.io (ERD PNG, 사용자가 손으로 내보냄)

**Spec:** `docs/superpowers/specs/2026-11-18-order-db-design.md` (4절 테이블, 5절 동작 규칙, 8절 파일)

## Global Constraints

- 범위는 DB만: DBML · DDL · extra SQL · ERD PNG · design/README · CHANGELOG · `pc/central/README.md` 문구. 웹 서비스 코드 · API · 인터페이스는 만들지 않는다.
- 테이블 13개: `account`, `product`, `stock_ledger`, `orders`, `order_item`, `trip`, `trip_item`, `status_history`, `alert`, `admin_action`, `stock_close`, `stock_count`, `app_setting` + 뷰 `v_in_flight`.
- 상태 · 사유 · 동작 값은 ENUM이 아니라 `text + CHECK`. 값 목록은 설계 문서 4절 표의 값을 **글자 그대로** 쓴다.
- `order_db.sql`은 손으로 고치지 않는다. 다시 만들 때 `design/db/tools/gen_sql.sh`만 쓴다.
- 적용 순서: `order_db.sql` → `order_db_extra.sql`. extra는 빈 DB에 `order_db.sql`을 적용한 직후에 오류 없이 돌아야 한다.
- 이름 규칙(계획에서 정함): CHECK는 `ck_<테이블>_<뜻>`, 트리거 함수는 `fn_<뜻>()`, 트리거는 `tg_<테이블>_<뜻>`, 부분 인덱스는 `ux_<테이블>_<뜻>`.
- 재고 잠금 키(계획에서 정함): `pg_advisory_xact_lock_shared(7001)` / `pg_advisory_xact_lock(7001)`.
- 원장 경유 표시(계획에서 정함): 원장 트리거만 `set_config('ifp.via_ledger', 'on', true)`를 켜고 `product.stock_qty`를 바꾼다.
- NOTIFY 채널(계획에서 정함): `ifp_events`, 내용은 JSON `{"t": <테이블>, "id": <키 문자열>, "status": <새 상태 또는 null>}`.
- 버전: DBML `Project` 노트 · design/README 표 · CHANGELOG에 **v1.0 · 2026-11-19**.
- 브랜치 `docs/design`. 커밋은 Conventional Commits, 한국어 설명. 끝에 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- `tests/`(저장소 맨 위, 추적 안 됨)는 건드리지 않는다. DB 시험은 `design/db/tests/`에 둔다.

## Review Focus

1. **마감 시작과 동시에 들어오는 원장 기록.** 원장 기록 트랜잭션이 공유 잠금을 쥔 동안 마감 시작(배타 잠금)은 기다려야 하고, 마감이 시작된 뒤 들어온 반출은 거절돼야 한다. → Task 4 `test_close_start_waits_for_ledger_txn`.
2. **원장을 거치지 않고 `product.stock_qty`를 바꾸는 UPDATE.** 앱 버그나 손 SQL로 재고가 기록 없이 바뀌면 안 된다. → Task 4 `test_direct_stock_update_rejected`.
3. **잘못된 바로잡기.** 같은 기록을 두 번 바로잡기, 출고 차감(`SHIP`)을 입력 오류로 바로잡기, 다른 상품 · 다른 수량으로 바로잡기는 모두 거절. → Task 4 `test_correction_*`.
4. **취소된 마감의 실사 행으로 재고 조정.** 원장이 취소된 마감의 `stock_count`를 가리키면 거절. → Task 4 `test_adjust_from_cancelled_close_rejected`.
5. **마감 중에 새로 등록한 상품.** 마감을 시작한 뒤 상품이 하나 더 생기면, 그 상품에 실사 행이 없을 때 확정이 막혀야 한다. → Task 5 `test_confirm_requires_row_for_new_product`.

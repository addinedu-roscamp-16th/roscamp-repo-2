# 사용자(고객) 주문 페이지 스토리보드 설계

- 작성일: 2026-11-19
- 상태: 승인됨 (2026-11-19)
- 산출물: `design/diagrams/사용자_스토리보드.drawio` (탭별 PNG로 내보내 제출), 생성 스크립트 `design/storyboard_tools/`

## 1. 목적

고객이 주문을 넣으면 시스템이 그 주문을 받아 처리할 수 있다는 것을 보여 주는 고객 웹 페이지의 화면과 동작 흐름을 장면 단위로 그린다. 관리자 스토리보드 v1.2와 짝을 이루는 **검토용 초안**이다.

### 목표
- 기능 검토 시트 "기능 목록"에서 사용 역할이 사용자 · 공통인 화면 기능이 모두 어느 장면엔가 나온다.
  - SCR-01 로그인
  - SCR-02 상품 검색 · 재고 확인
  - SCR-03 주문
  - SCR-04 진행 상태 표시 (실시간)
  - SCR-05 주문 취소 (일부: 접수됨일 때만)
  - SCR-09 결품 안내 (일부: 일부 출고, 담을 상품 없음 → 취소 안내)
  - OMS-03 재고 초과 거절
  - OMS-10 취소 가능 여부
  - OMS-13 결품 사용자 안내
- 모든 장면의 주문 상태 표시가 2절의 상태 대응표를 따른다.
- 장면마다 기능 ID와 시퀀스 메시지 번호를 적어 다이어그램 v2.4와 대조할 수 있다.

### 하지 않는 것
- 모바일 화면. PC 웹 브라우저만 그린다.
- 브라우저 푸시 · 소리 같은 실시간 알림. 알림은 페이지 위쪽 줄에만 보인다.
- 장애 · 결품 처리 중 · 서비스 일시 정지 · 마감 같은 내부 사정의 안내. 고객에게는 "준비 중"(또는 "접수됨")으로만 보인다.
- 재고 예약(OMS-07), 취소 처리 중 · 취소 상품 처리 중(OMS-11 일부). 구현 계획 미포함
- 픽셀 디자인 · 실제 문구 확정, 웹 코드

### 실패로 보는 경우
- 한 내부 상태가 장면마다 다른 말로 보인다.
- 준비 중 이후 주문에 [취소]가 보인다 (OMS-10: 접수됨에서만 취소).
- 고객 화면에 장애 · 마감 · 결품 처리 중 같은 내부 사정이 드러난다.

## 2. 정한 내용 (사용자 결정, 11-19)

- **상품 3종 · 이미지 (11-19 추가).** 미니멘토스 레인보우 · 과즙팡 비타민 마이구미 · 자유시간 Mini. 상품 줄은 이미지 · 이름 · 재고 · 수량 버튼, 내 주문 줄은 번호 · 상태 / 상품 수량 두 줄
- **주문 상세 패널 (11-19 추가).** 내 주문의 주문 번호를 누르면 오른쪽에서 숨겨진 상세 창이 내 주문 자리를 덮고 열린다. 주문 상품 · 지금 상태(접수됨이면 [취소]) · 시간별 진행을 보이고 [×]로 닫는다. 진행은 고객 상태 말이 바뀐 시각만(주문 DB 설계 4.6 order_status_history), 아직 안 온 단계는 회색, 열린 동안 WS로 저절로 더해진다. 같은 말 안의 내부 변화(담기 일시 중지 등)는 단계로 보이지 않는다
- **PC 웹 한 화면.** 왼쪽에 상품 목록(검색 · 재고 · 수량 · [주문하기]), 오른쪽에 내 주문 목록을 둔다. ※ 배치는 설계자 제안을 사용자가 받아들임
- **상태는 저절로 바뀜 (A안).** 내 주문 목록의 상태는 서버가 보내는 대로 바뀐다 (SCR-04, WS). 새로고침이 필요 없다.
- **알림은 페이지 위쪽 한 줄.** 알릴 일이 있을 때만 보이고 [확인]을 누르면 사라진다.
- **지연 안내 없음.** 장애나 마감 때문에 오래 멈춰도 "준비 중"으로만 둔다.

### 상태 대응표 (내부 상태 → 고객 화면)

| 내부 상태 (다이어그램 2. 주문) | 고객 화면 | [취소] | 위쪽 알림 |
|---|---|---|---|
| 접수됨 (마감 중 배정 보류 포함) | 접수됨 | 있음 | 없음 |
| 배정됨 · 담는 중 · 담기 일시 중지 · 주문 처리 보류 | 준비 중 | 없음 | 없음 |
| 운반 중 | 출고 중 | 없음 | 없음 |
| 출고됨 | 출고 완료 | 없음 | 없음 |
| 일부 출고됨 | 일부 출고 | 없음 | 못 담은 상품과 수량 (OMS-13) |
| 취소됨 (고객이 취소) | 취소됨 | 없음 | 없음 |
| 취소됨 (담을 상품 없음, D-14) | 취소됨 | 없음 | 상품이 없어 주문이 취소됨 (OMS-13) |
| 거절 (마감 뒤 재고 다시 확인, R-08) | 거절됨 | 없음 | 재고가 부족해 처리할 수 없음 |

- 주문할 때 재고 초과(OMS-03)는 주문을 만들지 않고 [주문하기] 아래에 바로 안내한다. 내 주문 목록에 줄이 생기지 않는다 (주문 DB 설계 5절 "주문 등록"과 같음).
- "거절" 상태 이름은 다이어그램 수정 요청 R-08에서 정해질 이름을 따른다.

## 3. 방식 (Approaches)

| 방식 | 내용 | 장점 | 단점 |
|---|---|---|---|
| **1. 생성 스크립트를 저장소로 옮겨 같이 씀 (선택)** | 관리자 스토리보드 생성 스크립트를 `design/storyboard_tools/`로 옮겨 공통 부분을 나누고, 고객 화면 모양만 더한다 | 두 스토리보드의 모양 · 범례가 같다. 검사기로 상태 대응표를 지킨다. 스크립트가 저장소에 남는다 | 정리 작업이 조금 더 든다. 관리자 스토리보드를 다시 만들어 같은지 확인해야 한다 |
| 2. 스크립트를 복사해 따로 고침 | 고객용 사본을 만든다 | 가장 빠르다 | 코드가 두 벌이고 여전히 저장소 밖에 있다 |
| 3. draw.io에서 손으로 | 관리자 파일에서 모양을 복사해 그린다 | 도구가 필요 없다 | 장면 20개 안팎의 상태 이름을 맞출 방법이 없다 |

선택 이유: 이 스토리보드의 핵심은 상태 대응표가 모든 장면에서 지켜지는 것이고, 검사기가 그 일을 한다. 관리자 스토리보드 스크립트도 지금은 세션 임시 폴더에만 있어 잃어버릴 수 있다.

## 4. 탭 구성

| 탭 | 내용 | 기능 · 시퀀스 |
|---|---|---|
| 0. 화면 구성 | 위쪽 알림 줄, 상품 · 내 주문 배치, 상태 대응표, 범례 | SCR-01 ~ 05 · 09 |
| 1. 평상시 주문 | 로그인 → 검색 → 수량 → [주문하기] → 접수됨 → 준비 중 → 상세 열기 → 출고 중 → 출고 완료 (상세의 진행이 함께 바뀜) | SCR-01 ~ 04 · 6-1-1 #1 · #8 · #15 · 6-1-3 #34 |
| 2. 재고 초과 거절 | 품절 상품은 수량을 못 고름, 재고보다 많으면 [주문하기] 아래 안내 | SCR-02 · 03 · OMS-03 · 6-1-1 #5 |
| 3. 주문 취소 | 접수됨 → [취소] → 확인 창 → 취소됨. 준비 중부터는 [취소] 없음. 누르는 순간 배정되면 "이미 준비가 시작되어 취소할 수 없습니다" | SCR-05 · OMS-10 · 6-4 #1 · #10 |
| 4. 결품 | 준비 중 → 일부 출고 + 위쪽 알림 → 상세에서 못 받은 상품 확인 / 담을 상품 없음 → 취소됨 + 위쪽 알림 | SCR-09 · OMS-13 · 6-2 #22 · #25 |
| 5. 마감 뒤 거절 | 오래 접수됨이던 주문 → 거절됨 + 위쪽 알림 | CEN-13 · R-08 |

로그인 장면은 관리자 스토리보드 0번 탭의 로그인 화면과 같은 모양으로 그린다 (역할이 사용자면 이 화면으로).

## 5. 만드는 방법

- `design/storyboard_tools/`
  - 공통: 장면 칸 · 설명 세 줄(고객 · 시스템 · 근거) · 범례 · 화살표 · draw.io 쓰기
  - 관리자 화면 모양 + 장면 + 검사 (지금 스크립트를 옮긴 것)
  - 고객 화면 모양 + 장면 + 검사 (새로)
  - 사용법 README
- 옮긴 뒤 관리자 스토리보드를 다시 만들어, 옮기기 전 스크립트의 출력과 같은지 비교한다. 같지 않으면 고객 작업을 시작하지 않는다.
- 고객 검사기 규칙
  - 화면의 주문 상태 말이 대응표의 고객 화면 칸에 있는 말뿐이다.
  - [취소]는 "접수됨" 줄에만 있다.
  - "장애 · 보류 · 일시 정지 · 마감 · 결품 처리" 같은 내부 말이 고객 화면 안에 없다 (설명 줄 · 근거 줄은 예외).
  - 탭마다 기능 ID가 근거 줄에 있다.
- 기록: design/README(문서 표 · 디렉터리), CHANGELOG
- 버전: v1.0 · 2026-11-19
- PNG 내보내기 · 커밋 · 컨플루언스 게시는 사용자가 요청할 때 한다.

## 7. 검수 반영 (2026-11-19, 검수자 2명: 고객 사용성 · 다이어그램 정합)

설계자 판단으로 더한 화면 규칙 (0번 탭 "화면 규칙" 노트):

- 한 주문 최대 4개(바구니 용량, 주문 DB 설계 4.5). 수량 버튼은 재고와 4개 안에서만 올라간다.
- 주문이 접수되면 고른 수량은 0으로 돌아간다. 재고 초과로 거절되면 재고를 다시 읽고 고른 수량을 재고까지 낮춘다.
- 재고 숫자는 주문 때 줄지 않고 출고(출고 완료 · 일부 출고)될 때 줄어든다 (6-1-3 #33, 재고 예약 없음).
- 알림이 여러 개면 쌓아 두고 "(1/2)"처럼 하나씩 보인다. 알림이 가리키는 주문 줄은 노랑으로 강조한다.
- 알림 문구는 다음에 할 일을 말한다 (예: "수량을 줄여 다시 주문해 주세요").
- 장면마다 ① 누르는 곳은 하나이고 고객 줄의 ① [버튼]과 같다. 화살표 라벨은 다이어그램 2. 주문의 상태 이름 또는 R-xx를 담는다.

다이어그램과 어긋난 곳은 다이어그램 수정 요청으로 냈다: R-11(기록 전 재고 초과 거절) · R-12(일부 출고 안내 시점) · R-13(취소 경합) · R-14(운반 중 보고), R-08 보완(고객 거절 안내).

미룬 것 (Minor): 로그인 실패 장면, 주문이 없는 첫 화면, 취소 확인 창 버튼 이름([닫기] → [주문 유지])과 "주문은 그대로 진행됩니다" 문구.

## 8. v1.1 (예정, 2026-11-19 사용자 결정) — "점검 중" 화면

**왜.** 서비스 전체를 정상 운영과 시험 모드로 나누기로 했다 (기능 COM-06, 주문 DB 설계 5절 "시험 모드", 다이어그램 수정 요청 R-20). 시험 모드에서는 주문 · 재고가 시험 DB에 있으므로 실제 고객의 주문을 받지 않는다. 그동안 고객 페이지는 **"점검 중"**으로 안내한다 (사용자 결정).

**언제 보이나**
- 서비스가 시험 모드로 켜져 있는 동안에만 보인다.
- 정상 운영의 마감 중(시험 모드에서 돌아온 뒤 운영 재개 마감 포함)에는 보이지 않는다. 마감은 지금처럼 고객에게 드러내지 않고, 주문도 받는다 (접수됨으로 대기).

**화면 (설계자 제안)**
- 로그인 전 · 뒤 모두 같은 한 화면이다. 상품 목록 · 내 주문 · [주문하기] · 로그인 창을 보이지 않는다.
- 가운데 문구: "지금은 시스템 점검 중입니다. 점검이 끝나면 다시 주문할 수 있습니다." 끝나는 시각은 알 수 없으므로 적지 않는다.
- 위쪽 알림 줄은 쓰지 않는다. 점검 중 화면 자체가 안내다.
- 고객 화면에 "시험 · 시험 모드" 같은 내부 말을 쓰지 않는다. 고객에게는 "점검"으로만 보인다 (1절 "실패로 보는 경우"와 같은 원칙).

**넘어가는 때**
- 모드를 바꾸려면 서비스를 내렸다가 다시 켠다. 열려 있던 고객 페이지는 연결이 끊기면 "연결 중…"을 보이며 다시 연결을 시도하고, 다시 연결된 서버가 시험 모드면 점검 중 화면으로 바뀐다.
- 점검이 끝나 정상 운영으로 다시 연결되면 평소 화면으로 돌아온다. 점검 전에 넣은 주문은 운영 DB에 그대로 있어 내 주문에 다시 보인다.
  - 점검 전부터 접수됨이던 주문은 운영 재개 마감을 확정할 때 재고를 다시 확인한다. 재고가 모자라면 거절됨 + 위쪽 알림(5번 탭과 같음).

**스토리보드 (v1.1에 더할 탭)**: "6. 점검 중"
1. 주문 화면을 보던 중 연결이 끊김 → "연결 중…"
2. 다시 연결 → 점검 중 화면 (상품 · 내 주문 없음)
3. 점검 중에 처음 들어옴 (로그인 전) → 같은 점검 중 화면
4. 점검이 끝나 다시 연결 → 평소 화면, 점검 전 주문이 그대로 보임 (재고가 모자랐으면 거절됨 + 알림)

근거 줄: COM-06 · R-20. 고객 검사기에 "점검 중" 화면에는 상품 · 내 주문 · [주문하기]가 없고 "시험"이라는 말이 없는지 규칙을 더한다.

**설계자 판단으로 남긴 것**
- 개발자가 시험 계정으로 고객 화면을 보는 기능은 두지 않는다. 시험 주문(시나리오 · 직접 주문, OMS-21)은 관리자 페이지의 시험 화면에서 넣고 확인한다. 고객 화면에서 시험 주문을 보고 싶다면 따로 정한다.

**v1.1 때 함께 고칠 것 (11-19 주문 DB 설계 결정에 따라)**
- 7절 "한 주문 최대 4개(바구니 용량)" → 주문 한 건의 최대 상품 개수는 운영 설정(OMS-20)을 따른다. 바구니 용량을 넘는 주문은 나뉘어 처리된다 (OMS-19).
- **나뉜 주문은 주문 하나로 보인다** (11-19 사용자 결정). 내 주문 목록에는 한 줄이고, 상태 말은 주문 DB 설계 4.4의 주문 요약 규칙을 따른다: 모든 바구니가 아직 시작 전이면 "접수됨"([취소] 있음), 하나라도 시작하면 끝날 때까지 "준비 중"(남은 바구니가 모두 운반 중이면 "출고 중"), 모두 끝나면 "출고 완료 · 일부 출고 · 취소됨". 일부 바구니가 먼저 출고되어도 "접수됨"으로 되돌아가지 않는다. 주문 상세에만 "바구니 1/2 출고"처럼 바구니별 진행을 보인다. 1번 탭(평상시 주문)에 나뉜 주문 장면을 하나 더한다.
- 2절 "거절 상태 이름은 R-08에서 정해질 이름": 내부 상태는 취소됨 + 사유 "마감 뒤 재고 다시 확인"으로 정해졌다 (R-19). 고객 화면 말 "거절됨"은 그대로 둔다.

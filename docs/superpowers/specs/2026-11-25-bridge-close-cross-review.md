## 4. 2차 결과

### 4.1 합의 (8명 같은 의견)

| E | 합의 |
|---|---|
| E1 | 마감 전이(시작 · 실사 열기 · 확정 · 취소)는 모두 **커밋 → 통보**. 7001을 쥔 채 ROS를 부르지 않는다. 보낼 일은 `stock_close` 행의 빈 ACK 칸으로 본다(새 outbox 표 없음, P7). ACK는 `WHERE status='IN_PROGRESS' AND hold_acked_at IS NULL` 같은 짧은 UPDATE, 0줄이면 늦은 ACK로 로그만. 화면에 "보류 전달 대기 n초"(P3). |
| E2 | 확정을 막는 것은 **재고에 영향이 있는 미처리 알림**뿐: 보고 상태 `SHIPPED` · `PARTIAL`이고 담은 수 > 0인 `NOT_ALLOWED` · `INVALID_REPORT`. `NOT_FOUND`는 경고만(`order_id` · `trip_id`가 비고 7001 전에 쓰여 상품에 이을 근거 없음, P5). 닫을 때 처리 코드 `SHIP_POSTED` · `COUNTED_ALREADY` · `ALREADY_FORCED` · `NO_STOCK_IMPACT`를 남긴다(P4). 같은 운반 건에 `SHIP`이 있으면 [차감] 버튼을 끈다. → [C] A6을 이 범위로 고침. |
| E3 | 열린 `NEGATIVE_STOCK`은 열린 시각과 관계없이 **모두** 확정을 막고, 확정 화면에서 닫는다(기본 "차감 안 함", P3). E10을 먼저 고친다. → [C] U3 추천 "막는다". |
| E4 | 보류 · 재개는 **목표 값 명령**. `request_id`는 보낼 때마다 새 UUID(기록용). 순서는 `(close_id 숫자, hold < release)`로 가린다(`close_id`는 IDENTITY라 늘기만 함). 보류 목록은 빼기 전용, 보류 중 들어온 `SubmitTrip`은 접수하되 주문판에 올리지 않음. 주문판을 거르는 주체는 **central 하나**(W-45 삭제, [IF] 242줄 정리). 재전송 주기의 원본은 [A] 5.2-3 · SB-12. → [C] B6의 고정 `request_id`와 A10의 "같은지만 비교"는 버림. |
| E5 | [A] 4.4 · 5.2-7 켜질 때 순서에 `/bridge/close_state` 다시 발행과 ACK 빈 보류 · 재개 다시 보내기를 넣는다(한 곳에 적고 다른 쪽은 링크). SB-13에 "마감 중 central 재시작" 추가. |
| E6 (일부) | `HELD` · `FLEET_RESTART` 건이 실사 열기를 막는 것은 옳다(바구니에 물건이 있을 수 있음). 화면에 막힌 이유를 보인다. 실사 중 늦게 온 `ASSIGNED`는 **반영하고 확정을 막는 알림**을 연다(로봇이 실제로 움직임). `SetAssignHold` 응답의 `in_progress_trips`만으로 판단하지 않는다(central은 HELD를 빼고 셈). 실사 열기도 7001 배타 + 트리거 확인. |
| E7 | SB-05 범위를 "**7001을 잡는 트랜잭션**"으로 넓힌다. 공유: 원장 · `apply_report` 전체 · 주문 접수 · 실사 저장. 배타: 시작 · 실사 열기 · 확정 · 취소. "예외 없음"은 마감 안의 행 순서를 정의로 적는 문장으로 고친다. **확정된 SB를 바꾸는 일이라 사용자 재확정 필요.** |
| E8 | `stamp`를 `ReportIn`에 받고 `LATE_REPORT` detail에 남긴다(인터페이스 변경 없음, 브리지 코드만). |
| E9 | `SHIP`에 부분 UNIQUE `(trip_id, product_id)`. 같은 상태 갈래에서는 차감하지 않는다. `FORCED_PARTIAL`이 같은 운반 건에 SHIP을 두 줄 쓰는지 [D]에서 확인(P3). |
| E10 | SAVEPOINT는 제약 이름 `ck_product_stock_qty`일 때만 `NEGATIVE_STOCK`으로 처리한다. |
| E11 | 원장 트리거가 7001 뒤에 `ledger_id`를 매기고(B1 P1 안: product UPDATE 뒤) `created_at := clock_timestamp()`. `ws_event.seq`는 받는 쪽이 조금 앞에서부터 겹쳐 읽는다. [A] 4.2.1에 "IDENTITY 순번은 잠금 전에 정해짐" 한 줄. |
| E12 | 실사 저장에 `Idempotency-Key`. 화면은 자동으로 다시 보내지 않고 "다시 세기"는 버튼으로만. 같은 키 재전송이면 `book_qty`를 다시 찍지 않는다. |
| E14 | 규칙 본문의 원본은 **[D] 5절 하나**. 결정 기록(ID · 상태 · 날짜)은 [A] 7장(SB) · [B](`CL-nn`, 새로). [A] 4.2.1은 표 · 예를 지우고 [D] 링크와 브리지 영향(55P03 → `accepted=false`, 풀 고갈, IDENTITY 순번)만 남긴다. 브랜치는 **`docs/sb-confirm`을 dev에 먼저 병합한 뒤 dev에서 고친다**(P8 안, 1차에 갈렸으나 2차에 8명 모두). 브리지 코드 · slice1 설계에 걸린 것(E8 등)만 `feat/bridge-slice1`에서 고친다. |

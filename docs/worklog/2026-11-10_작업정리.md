# 2026년 11월 10일 작업 정리

## 오늘 한 일

- 실제 로봇의 양쪽 카메라 ROI와 현재 관절 상태를 이용해 3D 위치와 물체 yaw를 계산하고, MoveIt 목표로 연결했다. yaw는 시야 점수가 높은 카메라를 기본으로 고르며 GUI에서 `0`(자동), `1`(왼쪽), `2`(오른쪽)으로 다시 선택할 수 있다.
- `sam_yaw_moveit.py`의 `E` 실행을 세 단계로 나눴다: 반대 팔 home 후 선택 팔 접근 → 그리퍼 닫기 → 선택 팔 상승. 각 단계가 성공해야 다음 단계로 넘어간다.
- 접근 목표의 기본 Z 오프셋을 물체 계산 좌표 기준 **+1 cm**로 바꿨다. 마지막 상승 목표는 **+20 cm에서 +5 cm**로 줄였다.
- 오른팔 그리퍼 닫기에서 물체 때문에 `0/100`에 도달하지 못하던 판정을 바꿨다. 수정한 Pi 브리지 코드는 `camera_code/sdk_goal_bridge.py`에도 복사했다. 닫기 성공 판정은 유효한 피드백이 `25/100` 이하에서 1.5초간 안정되는 조건이다. 이 판정만으로 물체를 확실히 잡았는지는 알 수 없다.
- PC 실행 감시기에서 반대 팔 이동과 그리퍼 동작 중 선택 팔 이동의 0.5° 기준을 각각 **3°**로 바꿨다.
- yaw 첫 후보가 실행 가능한 계획을 만들면 180° 후보 계획을 생략해 계획 시간을 줄였다.
- 양팔의 실측 기본 관절각을 MoveIt의 **`see_center`** 이름 자세로 추가했다. 기존 `home`은 변경하지 않았다.

## 마지막으로 확인한 동작과 남은 상태

- 최근 기록에서 오른팔 접근과 그리퍼 닫기는 성공했다. 당시 **20 cm 상승**은 MoveIt이 유효한 목표 자세를 찾지 못해 계획 단계에서 멈췄다. 이후 상승 거리를 5 cm로 수정했지만, **5 cm 상승의 실제 계획·실행 성공은 아직 확인하지 않았다.**
- 프로그램 종료 후 실제 양팔과 그리퍼의 현재 위치는 다시 확인해야 한다. 특히 물체를 잡은 상태라면 다음 명령 전 상태를 확인한다.
- 현재 SDK 브리지는 MoveIt 궤적의 중간 지점을 추종하지 않고 **마지막 관절 목표만 전송**한다. RViz에서 본 충돌 없는 경로와 실제 팔의 이동 경로가 다를 수 있다. 따라서 현재 방식은 양팔 충돌 회피를 보장하지 않는다.

## 내일 할 일

1. 양팔 실측 관절 상태와 그리퍼 상태를 확인하고, `see_center`가 MoveIt에서 의도한 각도로 표시되는지 확인한다.
2. 새 ROI로 계획한 뒤 단계별로 접근, 그리퍼 닫기, **5 cm 상승**을 확인한다. 각 단계에서 RViz 목표와 실제 위치의 차이를 기록한다.
3. 실제 팔의 관절 이동 기록을 받아 MoveIt 계획 경로와 비교한다. 두 팔이 가까운 구간의 최소 간격과 충돌 가능성을 확인한다.
4. 충돌 회피를 신뢰할 수 있도록, SDK 브리지가 마지막 목표만 보내는 구조를 MoveIt 궤적을 추종하고 실측 상태로 감시하는 구조로 설계한다. SDK가 중간 지점을 안정적으로 따라갈 수 있는지도 먼저 검증한다.
5. 물체를 잡은 상태에서의 그리퍼 피드백 판정과 물체 높이·캘리브레이션 오차를 추가로 확인한다.

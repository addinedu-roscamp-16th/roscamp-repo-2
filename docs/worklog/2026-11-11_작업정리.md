# 2026년 11월 11일 작업 정리

## 목표와 현재 방식

- 손목 카메라에서 사용자가 직접 고른 물체 ROI의 가로 중심을 640픽셀 영상의 중앙인 u=320으로 옮기는 것이 목표다. 아직 디텍션은 없고 같은 물체가 여러 개 있을 수 있다.
- 지금은 미세 조정을 반복하지 않고, 카메라 기하로 예측한 XY 위치로 한 번 이동한 뒤 예측이 얼마나 맞는지 확인하는 실험 단계다.
- ROI 중심 픽셀과 u=320에서 나가는 카메라 광선을 추정 물체 높이의 평면과 교차시키고, 두 교차점의 XY 차이를 보정량으로 계산한다. 이 계산은 물체 평면 높이, 손목 카메라 자세와 보정값에 의존한다.

## 오늘 한 일

- 오른팔 카메라는 5001번, 왼팔 카메라는 5000번 포트를 사용한다. 선택한 팔이 물체 6 cm 위로 접근하면 그 팔의 실시간 카메라에서 ROI를 지정할 수 있다. 오늘 배치에서는 오른팔 카메라에 물체가 중앙에 보였고 왼팔은 정면을 봐 물체가 보이지 않았다.
- 초기 home 명령이 성공 메시지만 출력하고 실제로 움직이지 않는 문제를 조사했다. 당시 1번·5번 관절이 설정된 각도 범위를 넘어선 상태였고, 사용자가 이를 풀어 현재 관절각을 다시 읽었다. 이 문제는 해결됐다고 확인했다.
- 실제 하드웨어의 관절 흔들림 때문에 접근 목표 도착 판정의 허용 오차를 5도로 높였다. 이후 수직 하강은 SDK MoveL로 시도했으나, 한 차례 실제 피드백이 1.5초 이상 갱신되지 않아 중단된 적이 있어 피드백 방식도 확인 대상이다.
- 매칭된 특징점들의 광학축 depth를 출력하도록 했다. 이 depth는 특징점의 깊이이며 그리퍼가 잡을 높이와 동일하다고 볼 수 없다.
- 하강은 기존에 SDK의 직선 좌표 이동으로 6 cm 명령하도록 구현했지만, 현재 예측 검증 흐름에서는 자동 하강과 그리퍼 닫기를 실행하지 않는다.
- 기존 ROI 가로 정렬은 계산한 XY 보정량을 최대 3 mm로 잘라 반복했다. 하드웨어 흔들림과 위치 오차를 고려해 이 미세 보정 방식을 현재 실험에서 제외했다.
- 로컬 코드는 기하학적으로 계산한 XY 보정량을 최대 80 mm 범위에서 한 번에 명령하도록 변경했다. MoveIt은 목표 자세와 관절 변화량을 사전 확인하고, 실제 XY 이동은 Pi SDK의 직선 좌표 이동 서비스로 요청한다. 한 캡처에서 이 이동은 한 번만 허용한다.
- 이동 후 카메라는 계속 켜 둔다. 같은 물체를 다시 ROI로 그리면 이동 후 가로 중심 u와 u=320까지의 픽셀 오차가 출력된다. 동일한 물체가 여러 개 있는 상황에서 자동 템플릿 추적이 다른 물체를 잡을 수 있어, 이번 결과는 사람이 같은 물체를 확인하며 측정한다.
- 관련 Python 파일은 문법 검사를 통과했다. 그러나 새 SDK 이동 서비스를 Pi에 배포하거나 실제 로봇에서 검증하지는 못했다. 이전 원격 접속 시도는 SSH 인증 실패로 끝났다.

## 오늘 로그와 남은 문제

1. capture_20261111_201557_374208: XY 명령은 [+1.88, +2.34] mm였지만 실측 TCP 변화는 [+0.61, -1.23, -9.43] mm, 자세 변화는 3.3도였다. 당시 방식은 MoveIt 계획의 마지막 관절 목표를 SDK로 보냈고, Z가 9.43 mm 내려가 정렬 검증에서 중단됐다. 그 뒤 하강과 그리퍼 닫기는 실행되지 않았다.
2. capture_20261111_202624_283593: 3 mm 정렬 목표에 한 관절을 32.6도 바꾸는 MoveIt 경로가 나왔다. 당시 12도 제한에 걸려 실행 전에 중단됐다. 작은 TCP 목표가 작은 관절 이동을 뜻하지 않는다는 사례다.
3. 새 한 번 이동 방식은 로컬 파일만 수정됐다. Pi에서 새 /right/sdk_linear_xy_tenth_mm 서비스가 실행되지 않으면 PC worker는 이동 전에 중단한다. 실제 XY 방향, 이동량, Z와 자세 유지 여부는 아직 모른다.
4. 손-눈 캘리브레이션 오차는 약 1.5 cm이며, 실제 잡기에서 깊이 차이도 문제다. ROI가 가로 중앙에 와도 그리퍼가 잡을 높이까지 맞았다는 뜻은 아니다.
5. 일반 MoveIt 실행 브리지는 계획 궤적의 모든 지점을 추종하지 않고 SDK의 최종 관절 목표를 보낸다. 새 XY 서비스도 MoveIt 계획 궤적을 재생하지 않으므로 실제 직선 이동 경로와 주변 물체를 별도로 확인해야 한다.
6. 현재 원인이 구분되지 않은 항목: 물체 높이 평면 가정, 카메라 내부 및 손-눈 보정, 실시간 관절 상태, SDK 기준 좌표계와 MoveIt base_link의 축 정렬, 로봇 자체 위치 오차.

## 내일 할 일

1. 움직이기 전에 양팔의 실측 관절각, TCP, 그리퍼 상태와 작업 공간을 확인한다. 오늘 실패한 캡처는 재실행하지 않고 새로 촬영한다.
2. 수정된 pinky_ws/src/jetcobot_dual_real/robot_bridge/sdk_goal_bridge.py를 선택한 팔의 Pi에 복사하고 브리지를 재시작한다. 오른팔 Pi는 192.168.0.22, 왼팔 Pi는 192.168.0.33이다. native_interpolation:=true와 새 /right/sdk_linear_xy_tenth_mm 또는 /left/sdk_linear_xy_tenth_mm 서비스가 있는지 확인한다. 자세한 실행 명령은 pinky_ws/src/jetcobot_dual_real/README.md를 따른다.
3. 새 ROI로 접근한 뒤 물체가 움직이는 팔 카메라에 보일 때 ROI를 선택한다. 예측 XY 이동량과 명령량, 실측 TCP XYZ 및 자세 변화를 기록한다. MoveIt의 관절 변화 제한에 걸리면 실행하지 않고 계획값을 기록한다.
4. 한 번 이동한 뒤 카메라에서 같은 물체를 다시 ROI로 선택하고 이동 전후 u와 |u-320|를 비교한다. 자동 하강과 그리퍼 닫기는 이 실험에서 하지 않는다.
5. 예측 방향과 실측 TCP 방향이 다르면 SDK와 MoveIt 기준 축 및 손목 카메라 보정을 확인한다. 방향은 맞지만 픽셀 이동량이 다르면 물체 평면 높이와 카메라 보정을 확인한다. Z 또는 자세가 흔들리면 SDK 직선 이동과 상태 피드백을 먼저 조사한다.
6. 예측 이동이 실제로 재현되는 것을 확인한 뒤에만 20픽셀 허용 오차, 잡기 깊이, 하강 및 그리퍼 닫기 재도입을 결정한다.

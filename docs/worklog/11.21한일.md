# 2026년 11월 21일 작업 정리

대상은 `roscamp-repo-2`의 `Phondy` 실물 JetCobot 양팔 픽앤플레이스다. 기준은 [11월 20일 작업 정리](https://github.com/addinedu-roscamp-16th/roscamp-repo-2/blob/Phondy/docs/worklog/2026-11-20_작업정리.md)와 [양팔 협동 상태 설계](https://github.com/addinedu-roscamp-16th/roscamp-repo-2/blob/Phondy/docs/worklog/2026-11-20_양팔_협동_상태_설계.md)다. 오늘은 PC 앱 코드와 문서를 수정했고, 실물 동작이나 Pi 배포는 확인하지 않았다.

## 목표

주문 상품만 대상으로 경로를 준비하고, 핑키 도착 후 양팔이 계획 때문에 동시에 멈춰 있는 시간을 줄인다. `see_center`를 담기 후 복귀 자세로 사용한다. 핑키 도착 신호와 주문 서비스가 연결되기 전에는 ROI ID로 품목을 지정하고 작업자가 `E`를 눌러 실행을 시작한다.

일반 접근과 선행 접근의 worker 명령 조립을 통합하고, 읽는 곳이 없던 정지 상태 변수를 제거했다. 현재 실행 게이트는 한 번에 한 목표를 처리한다. 오늘 구현한 속도 개선은 계획과 실행의 시간 중첩 및 복귀 후 인계에 해당한다.

### 복구 범위

- 접근 계획만 실패해 팔이 움직이지 않은 경우 `U`로 같은 상품을 다시 계획한다.
- 그리퍼 열림과 부착 모델 제거가 기록된 뒤 복귀에 실패한 경우에는 작업자가 물체가 바구니에 있음을 확인하고 양팔을 `see_center`로 복구한 뒤 `U`를 누른다. 이때 이미 담은 상품은 다시 집지 않는다.
- 물체 보유 여부나 동작 결과가 불확실하면 복구를 진행하지 않는다. 기록 파일은 현장 확인용이며 앱을 재시작하면 자동으로 이어지지 않는다.

## 다음 개발

1. 기존 모의 worker 테스트를 직접 담기 → `see_center` 복귀 → 다음 팔 인계 흐름으로 갱신한다. 상품을 한 번만 꺼내는지, `P` 이후 늦게 온 결과가 실행을 시작시키지 않는지, 담기 후 복구가 중복 집기를 막는지, 정지 중 계획 대기 시간이 올바르게 집계되는지 확인한다.
2. 상품을 처음 본 시각과 관절 피드백을 확인한 시각을 분리한다. 새 관절값으로 다시 계획할 때 오래된 상품 위치까지 새로 관측한 것처럼 처리하지 않도록 한다. 복귀 끝 자세 전달도 로그 문자열 대신 구조화된 데이터로 바꿔 실행 직전 재계획 결과와 일치시킨다.
3. 순차 실행과 복구가 실물에서 안정된 뒤 첫 팔 운반과 둘째 팔 접근을 하나의 양팔 경로로 계획한다. 상대 팔의 비켜주기 자세 대신 다음 주문 상품의 접근 자세를 후보로 검증하고, 두 팔의 경로가 함께 성립할 때 실행한다.
4. 팔 배정을 거리에서 도달 가능성과 예상 완료 시간 중심으로 개선한다. 좌우 교대 원칙을 유지하면서 한 팔에 접근 불가능한 상품이 배정되면 같은 팔 차례에 다른 주문 상품을 검토한다. 물체 검출 변경은 이번 범위에서 제외한다.

# 양팔 협동 픽앤플레이스 상태 설계

2026-11-20 사용자 확인 사항. 이 문서는 구현 전 요구사항 정리이며, 코드 변경이나 실물 검증 결과가 아니다.

## 목표

여러 상품을 왼팔과 오른팔에 번갈아 배정한다. 한 팔이 상품을 집거나 바구니에 담는 동안 다른 팔은 가능한 작업을 진행한다. 상품 구역과 바구니 구역은 각각 한 번에 한 팔만 점유한다. 다음 팔의 담기 경로를 미리 계획해 바구니가 비는 즉시 실행한다.

## 팔별 상태

| 상태 | 의미 |
| --- | --- |
| `idle` | 맡은 작업 없이 대기 |
| `pick_waiting` | 상대 팔이 상품 구역을 점유하여 집기 대기 |
| `picking` | 상품을 집고 들어 올리는 중 |
| `place_waiting` | 상품을 잡았으나 상대 팔이 바구니 구역을 점유하여 담기 대기 |
| `placing` | 바구니에 상품을 놓고 `see_center`로 복귀하는 중 |
| `paused` | 거리 기준 정지, 집기 재시도 횟수 초과, 인식 오류(`PHD-08`) 등으로 해당 팔 일시 정지 |
| `error` | 장애로 전체 서비스 일시 정지 |

`retrying` 상태는 이번 구현 범위에서 제외한다. 집기 재시도 횟수를 초과하면 `paused`로 전환한다.

## 자원 점유와 해제

### 상품 구역

- `picking`을 시작한 팔이 상품 구역을 점유한다. 다른 팔은 필요하면 `pick_waiting`에 들어간다.
- 집던 팔의 **로봇 베이스 기준 TCP `z`가 그 팔의 `see_center` TCP `z` 이상**이 되면 상품 구역 점유를 해제한다.
- 점유가 해제되면 기다리던 반대 팔이 바로 집기를 시작한다.

### 바구니 구역

- `placing`을 시작한 팔이 바구니 구역을 점유한다. 다른 팔은 필요하면 `place_waiting`에 들어간다.
- 상품을 놓는 순간에는 점유를 해제하지 않는다. **놓은 팔이 `see_center`로 복귀한 뒤** 바구니 구역 점유를 해제한다.
- 점유가 해제되면 기다리던 팔이 준비된 담기 경로로 바로 출발한다.

## 작업 순서와 겹쳐 실행할 구간

1. 인식된 상품을 왼팔·오른팔에 번갈아 배정한다. 한 팔의 계획 비용이 조금 낮다는 이유로 연속된 상품을 모두 그 팔에 배정하지 않는다.
2. 첫 팔이 집기를 시작한다. 그 팔이 `see_center` 높이까지 물체를 들어 올려 상품 구역을 비우면 다음 팔이 집기를 시작한다.
3. 물체를 잡은 팔은 바구니가 비어 있으면 담기를 시작한다. 바구니가 점유 중이면 물체를 든 채 `see_center`로 먼저 올라가 `place_waiting` 상태에서 기다린다.
4. 기다리는 팔의 **다음 담기 경로는 양팔이 `see_center`에 도착해 있을 미래 상태를 시작점으로 삼아**, 앞 팔이 담기·복귀하는 동안 미리 계산한다. 실제로 두 팔이 먼저 `see_center`에 도착할 때까지 계획을 미루지 않는다.
5. 앞 팔이 상품을 놓고 `see_center`로 복귀하면 바구니 점유를 해제한다. 실제 관절 상태와 충돌 조건이 사전 계획의 가정에 맞는지 확인한 뒤, 다음 팔이 계획 대기 없이 담기를 실행한다.

## 구현 시 지켜야 할 구분

- 상태는 **팔별 상태**이고, 상품 구역·바구니 구역 점유는 두 팔이 공유하는 별도 상태다.
- `paused`는 해당 팔의 일시 정지, `error`는 전체 서비스의 일시 정지다.
- 사전 계획이 끝난 것과 실물에서 즉시 실행 가능한 것은 다르다. 실행 직전에는 실제 팔 자세, 잡은 물체 상태, 충돌 조건을 다시 확인한다.

## 아직 정하지 않은 세부값

- 첫 상품을 어느 팔에 배정할지 정하는 기준.
- `paused`에서 복귀하는 조건과 조작 방법.
- 거리 기준 정지와 `PHD-08` 인식 오류를 판정하는 구체적인 입력·임계값.

# 2026년 11월 12일 작업 정리

## 오늘 한 일

- ROI 기반 보정, SDK XY MoveL, MoveIt 경로 실행에서 이어진 문제들을 검토했다.
- 오른팔 SDK 경로에서 경유점 추종이 실패한 로그를 분석했다. 기존 브리지에는 2점 선행 큐 설정이 없었고, 새 브리지에는 lookahead depth 2가 적용됐다.
- 경유점 속도 설정 `path_sdk_speed`를 추가해 속도 10~100을 설정할 수 있게 했다. 경유점마다 10으로 고정되던 값을 설정값으로 바꾸고 테스트했다.
- SDK 큐 삭제가 확인되지 않으면 다음 경로 명령을 거부하도록 브리지를 수정했다.
- MoveIt 계획 충돌 형상의 기본 패딩을 링크당 5 cm로 설정하고 계획 전용 상태에서 적용 여부를 확인했다.
- 사용자가 원하는 것은 끝점 주행이 아니라 MoveIt 회피 경로 주행임을 재확인했다. 끝점 주행 제안은 철회했다.
- 관련 테스트 32개와 패키지 빌드가 통과했다. Pi에는 변경된 브리지를 배포하지 않았다.

## 발생한 이슈

1. 오른팔 경로에서 경유점 추종 실패가 반복됐다. 실측 팔이 다음 경유점으로 진행한 상태에서 계획 경로 편차가 중간 허용 기준 2°를 넘어 실패한 사례가 있었다.
2. 속도 15, 큐 깊이 2, 경유점 간격 6° 시험에서 사용자는 움직임이 “윙~윙~” 끊기고 반동이 있다고 보고했다. 313개 계획 지점이 16개 SDK 명령으로 줄었지만 MoveIt의 시간 정보는 SDK에서 재생되지 않는다.
3. 경로 중단 뒤 `clear_queue()`가 `-1`을 반환해 대기 명령 삭제가 확인되지 않았다. 중단 뒤 관절 상태를 세 번 읽었을 때 값은 같았지만 큐 삭제 성공을 증명하지는 않는다.
4. 이전 경유점을 기준으로 한 큰 관절 오차는 팔이 이미 다음 점으로 진행한 결과일 수 있어, 그 수치만으로 관절 처짐량을 단정할 수 없다. 멈출 때 숙이는 현상의 원인은 확인되지 않았다.
5. 5 cm 충돌 패딩은 계획 장면에 적용됐지만, 실패한 전체 경로의 안전성이나 실제 로봇 간 물리적 여유를 입증하지 않는다.

## 내일 할 일

1. 오른팔 Pi의 최신 `sdk_path_bridge.py`를 배포하고 기존 브리지를 종료한 뒤 재시작한다. 로그에서 큐 깊이, SDK 속도, 경로 명령 수를 확인한다.
2. 팔 사이를 충분히 띄운 상태에서 짧은 MoveIt 경로를 시험한다. 비교 시작값은 경유점 간격 6°, SDK 속도 10, 명령 간격 0.5초, 큐 깊이 2로 두고 반동과 실측 편차를 기록한다.
3. `clear_queue()`가 다시 `-1`이면 추가 경로 실행을 멈추고 Pi의 SDK 응답과 직렬 통신을 확인한다. 최신 브리지는 큐 삭제가 확인되지 않으면 새 명령을 거부한다.
4. 실행 전 계획 경로 전체를 RViz와 실제 작업 공간에서 확인하고, 경유점 진행과 경로 편차를 기록한다. 허용 오차를 높여 오류를 숨기지 않는다.
5. 멈출 때 숙임이 재현되면 관절별 목표·실측 시계열과 서보·하중 상태를 수집해 원인을 구분한다.

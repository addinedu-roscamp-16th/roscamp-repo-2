## 한 줄 요약

관제가 **"초코바 N개 담아"** 명령을 보내면 Phody가 사람 손 없이 사진 찍기 → 인식 → 두 팔로 집어 바구니에 담기까지 하고 결과를 돌려주는 연결을 만들었다. 팔 상태 보고와 운영 모드 받기도 된다. 팀 UI가 아직 없어서 **가짜 관제 프로그램**으로 시험했다.

## 1. 이번에 된 것

| 기능 | 관제 쪽에서 보이는 이름 | 상태 |
| --- | --- | --- |
| 담기 명령 받기 | `/workcell/fill_basket` | 완료. 실물에서 받기 · 거절 · 인식 · 집기 시작 · 멈춤 보고 확인 |
| 팔 상태 보내기 (초당 5번) | `/arm_left/state`, `/arm_right/state` | 완료. 실물 확인 |
| 운영 모드 받기 | `/arm_left/set_mode`, `/arm_right/set_mode` | 완료. 실물 확인 |
| 시험용 가짜 관제 | (Phody 쪽 터미널 프로그램) | 완료. 실물 시험에 사용 |

- 팀 정의 패키지 `fleet_interfaces`(dev 브랜치)를 **그대로** 썼다. 다만 dev 빌드 목록에 `ArmState`가 빠져 있어서 우리 복사본에만 한 줄 넣었다(아래 4장 FIX-5).
- 기존 사람용 화면 · 키(P 정지 등)는 그대로 쓸 수 있다. 관제 연결을 끄면(`fleet:=false`, 기본값) 전과 똑같이 동작한다. 실물로 확인했다.

## 2. 담기 명령은 이렇게 동작한다

1. 관제가 `fill_basket`(상품 코드, 개수, 작업대 `WORK`)을 보낸다.
2. Phody가 먼저 받을 수 있는지 본다. 안 되면 바로 실패 결과와 이유를 돌려준다.

   | 이유 | 언제 |
   | --- | --- |
   | `MODE_MISMATCH` | 모드를 아직 못 받았거나, 두 팔 모드가 다름(한 팔 NORMAL · 한 팔 TEST) |
   | `NOT_READY` | 이미 담는 중이거나, 팔이 멈춰 있거나, 물건을 쥐고 있음 |
   | `UNKNOWN_TARGET` | 작업대가 `WORK`가 아니거나, 모르는 상품 코드 |

3. 받으면 두 팔 카메라로 사진을 찍고 상품을 찾는다.
4. 찾은 것 중 **요청한 개수만** 고른다. 각 팔 차례에 **자기 쪽에 가까운 것**부터 고른다(멀리 뻗으면 팔이 기울어 못 드는 일이 있었음).
   - 예: 3개가 보이고 2개 요청 → 왼팔 쪽 1개, 오른팔 쪽 1개를 집고 1개는 남긴다.
5. 두 팔이 번갈아 집고 바구니에 담는다. 두 팔은 동시에 움직이지만 바구니에는 한 팔씩 들어간다.
   - 한 팔의 **계획(움직이기 전 계산)이 실패**하고 남는 상품이 있으면, 남는 것 중 그 팔에 가까운 것으로 다시 계획한다.
6. 진행 중에는 0.5초마다 **움직이는 팔마다** 진행 상황을 보낸다(두 팔이 다 움직이면 둘 다).
   - 단계 이름: `CAPTURING`(사진) · `PICKING`(집기) · `TO_BASKET`(바구니로) · `PLACING`(담기) · `RETURNING`(돌아오기)
7. 끝나면 결과를 보낸다.

   | 경우 | 성공 | 이유 |
   | --- | --- | --- |
   | 다 담음 | 예 | — |
   | 요청보다 적게 보여서 보인 만큼만 담음 | 예 | `OUT_OF_STOCK` |
   | 집기 단계(계획 · 위치 맞추기 · 잡기)에서 멈춤 | 아니오 | `PICK_FAILED` |
   | 그 밖에 팔이 멈춤 | 아니오 | `ARM_FAULT` |
   | 관제가 취소 | 아니오 | `CANCELED` (팔은 그 자리에서 멈춤. 쥔 물건은 쥔 채) |

   - "담은 수"는 바구니 위에서 집게를 연 횟수다(바구니 센서는 없음).
   - 멈추면 Phody는 그 자리에 서서 사람을 기다린다. 사람이 확인하고 관찰 자세로 되돌린 뒤, 관제가 다시 명령을 보내면 된다.

## 3. 오늘 실물 시험 결과

| 시험 | 결과 |
| --- | --- |
| 관제 연결 끄고 평소처럼 2개 담기 | 정상. 전과 같음 |
| 모드 받기 전 담기 명령 | `MODE_MISMATCH`로 거절됨 |
| 모드 `NORMAL` 보내기 | 두 팔 모두 받아들임 |
| 담기 명령 (3개 놓고 2개 요청) | 사진 · 인식 3개 · 2개 고르기 · 왼팔 계획 · 접근까지 정상 |
| 사람이 P로 정지 | 결과가 실패로 돌아오고 팔 상태가 바뀜. 정상 |
| **끝까지 다 담기** | **아직 못 함** — 아래 5장 1번 |

## 4. 팀에 부탁할 것 (전에 보낸 요청에 더해)

| 번호 | 내용 |
| --- | --- |
| FIX-1 | `/arm_left/state` · `/arm_right/state`를 contract에 넣어 주기 (회의에서 넣기로 함). 들어올 때까지 Phody는 임시 이름표를 쓴다 |
| FIX-2 | `ArmState`에 `PAUSED` · `PICK_WAITING` · `PLACE_WAITING` 값과 명세 칸 추가. 지금은 없어서 **멈춘 팔이 `ERROR`로 보인다**(이유는 `detail`에 적힘) |
| FIX-5 (새로) | dev의 `fleet_interfaces/CMakeLists.txt` 빌드 목록에 `msg/ArmState.msg`가 빠져 있다. 파일은 있는데 빌드가 안 된다. 한 줄 추가 부탁 |
| 상품 코드 | 코드 목록을 알려 주기. 지금은 `chocobar` 하나로 시험 중 |
| 실패 이유 | 사람이 P로 멈춘 경우, 카메라 · 인식 오류인 경우의 이유 코드를 정해 주기. 지금은 임시로 `ARM_FAULT`, `RECOGNITION_ERROR` |
| 팔 오류 설명 | [로봇팔 오류와 상태 설명](로봇팔_오류와_상태_Phody_사람용.md)을 보고 다음 회의에서 정하기 |

## 5. 남은 일

1. **미세조정(바 위에서 위치 맞추기) 인식 개선** — 지금 가장 급함.
   - 바를 3개 이상 빽빽하게 놓으면 카메라에 바 2개가 붙어 보여서 위치 맞추기가 바를 못 찾는다(오늘 시험이 여기서 멈춤).
   - 근접 사진을 새로 모아 YOLO 박스 검출로 바꿀 예정. 사진은 Phody 담당이 모은다.
2. 카메라 창: 움직이는 팔마다 카메라 창을 띄우고 위에 LEFT / RIGHT 표시.
3. 멈춘 뒤 이어서 하기(`U`)가 실제로 잘 안 된다. 따로 고칠 일.
4. 팀 답이 온 뒤 2차: 락(`set_lock`, 회의 답: 힘 빼기), 고장 해제, heartbeat 끊김 처리, 멈춤 · 이어서 명령.
5. 통합 시험 때 `ROS_DOMAIN_ID`를 83 → 6으로 바꾼다(개발 중에는 83).
